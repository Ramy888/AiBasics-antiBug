What it is

A debugging drill. You give antiBug a commit from a public GitHub repo, pasted code, or the built-in sample. Claude plants one realistic logic bug that still compiles, and you race the clock to click the broken line. Then you see the original line next to the planted one, with a short lesson.

The main pieces:

  • The page (app/page.tsx) runs the setup → planting → hunt → reveal phases in the browser.
  • Five API routes (app/api/*/route.ts): commits, drill, guess, hint, reveal.
  • The saboteur (lib/saboteur.ts + lib/validate.ts) asks Claude for a bug and checks it mechanically.
  • The seal (lib/seal.ts) encrypts the answer into a token, so the browser carries the drill but can't read where the bug is. There is no database.

One action, end to end: “Try a sample”, then click a line

Reference route: you can follow these stops in the editor; they were not toured live.

1

The click starts a drill: app/page.tsx

“Try a sample” calls startPaste(SAMPLE.code, SAMPLE.filename) (sample in lib/sample.ts). That calls plant(), which posts the code to /api/drill and keeps the returned drill.token. Search for async function plant.

2

The server plants and seals: app/api/drill/route.ts → lib/drill.ts → lib/saboteur.ts

The route first counts the visitor's drills (takeDrill in lib/ratelimit.ts; on Cloudflare a Durable Object in lib/drill-limiter.ts). drillPasted then calls plantBug. This loop asks Claude for a mutation, runs checkMutation (lib/validate.ts: same line count, still parses, changes runtime behaviour), and retries up to 3 times with the checker's reason. The answer is sealed with AES-GCM by seal().

3

A click is judged: guess in app/page.tsx → app/api/guess/route.ts

guess(line) posts the token and the line. The route calls open(token) and compares the line with bugLines. If they differ, it returns temperature() from lib/shared.ts: hot within 3 lines, warm within 10. The page adds the 10-second penalty itself (WRONG_PENALTY).

A practice to reuse: never ship model output unchecked

Decision. Claude's bug is never trusted as is. Each suggestion passes a deterministic checker before anyone sees it. When the checker rejects it, the reason goes back into the next prompt (plantBug loop, lib/saboteur.ts). It rejects edits that only touch types or comments (identical transpiled output) and edits that change the line count, which would break click-to-guess. What it can't judge, a person still has to: Ramy's final review found a drill that planted a skipped test in a test file, which led to the non-test-first ranking in lib/target.ts (checklist Revisions).

Evidence. tests/validate.test.ts and tests/saboteur.test.ts run the checker and the retry loop with a mocked Claude. npm run test:live runs one real planting.

Use it again. Whenever an LLM produces something your program acts on (a patch, a query, JSON, a plan), write down the rules a correct output must meet. Check them in code, feed the failure reason back, and cap the retries.
